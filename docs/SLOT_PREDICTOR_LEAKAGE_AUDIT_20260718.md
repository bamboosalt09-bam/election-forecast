# 슬롯 예측변수 결과누출 감사 (2026-07-18)

## 결론

현재 scored 선거 `pres_2002`, `pres_2007`, `pres_2012`, `pres_2017`,
`pres_2022`에서 실제 전국 1위 후보는 모두 슬롯 A다. 그런데 활성 Ridge
예측변수에는 `slot_A`, `slot_B`가 직접 포함되고, `slotA_prior`,
`slotB_prior`도 슬롯과 지역 prior의 상호작용으로 포함된다.

슬롯 A를 예측 시점에 정하는 outcome-blind 규칙과 `available_date`가 없다.
따라서 현재 슬롯 변수는 사실상 사후 승자 표시와 정렬되어 있으며,
forecast 입력으로 방어할 수 없다. 기존 nested 성능은 순수 사전예측
성능으로 인용해서는 안 된다.

## 2012 단계 분해

| 단계 | A 전국 예측 | A 실제 | 지역 투표수 가중 MAE |
|---|---:|---:|---:|
| Ridge 원시 정규화 | 62.542 | 51.773 | 10.769 |
| 단일화/withdrawn 보정 | 58.217 | 51.773 | 6.456 |
| 정당 지역층 보정 | 57.728 | 51.773 | 5.964 |
| 당내 맥락 보정 | 57.472 | 51.773 | 5.739 |
| public treatment 이후 | 57.979 | 51.773 | 6.214 |
| electorate gain 이후 최종 | 57.959 | 51.773 | 6.194 |

오차는 후처리에서 새로 생긴 것이 아니다. Ridge 원시값에서 이미 A가
`+10.769%p` 과대예측된다. 후처리들은 대체로 편향을 줄였고,
public-treatment 단계만 약 `0.51%p`를 다시 A 쪽으로 이동시켰다.

## 변수군 제거 진단

2012 fold에서 직접 슬롯 더미만 제거하면 최종 A 예측은 `50.445%`, 지역
가중 MAE는 `2.065%p`가 된다. 모든 슬롯 파생변수까지 제거하면 A 예측은
`49.818%`, MAE는 `2.392%p`다.

| predictor set | 전체 nested 지역 MAE | 전국 점 MAE | 2012 지역 MAE | 2012 전국 MAE |
|---|---:|---:|---:|---:|
| 활성 10변수 | 4.613 | 3.441 | 6.194 | 6.185 |
| `slot_A`, `slot_B` 제거 | 6.470 | 5.694 | 2.065 | 1.328 |
| 모든 슬롯 파생변수 제거 | 6.715 | 6.128 | 2.392 | 1.955 |

슬롯 제거가 2012만 개선하고 다른 선거를 크게 악화시키는 것은 활성
성능이 사후 승자 정렬에 의존한다는 증거다. 직접 슬롯 더미를 제거한
전국 MAE는 2007 `11.467%p`, 2017 `7.998%p`, 2022 `6.387%p`다.

## 부차적 발견

rolling 학습에서 목표 test는 `scored_contest_rows()`로 제한하지만 과거
train은 같은 필터를 통과하지 않는다. 그 결과 2012 fold 학습에는 평가
분모에서 제외한 2002 C 슬롯도 들어간다. 다만 이 행을 제거하면 2012
MAE가 `6.194 -> 6.607%p`로 악화하므로 주원인은 아니다.

2007 대비 2002의 시대가중치를 높이면 2012 MAE가 일부 감소하지만,
슬롯 제거 효과보다 작다. 2007 상대가중치 1.0에서 MAE `6.006%p`, 0.25에서
`4.957%p`였다. 이 값은 2012 결과를 본 사후 진단이며 채택값이 아니다.

## 결정

1. 기존 활성 설정과 산출물은 재현을 위해 보존한다.
2. 기존 nested `4.613%p`, 전국 점 `3.441%p`는 오염된 진단값으로 표시한다.
3. 슬롯 A/B를 제거한 뒤 후보의 사전 경쟁력, 진영, 현직성, 당 규모 같은
   outcome-blind 속성으로 대체하는 새 기준모델이 필요하다.
4. 새 기준모델의 변수와 규칙은 성능을 보기 전에 고정하고, 2025 결과는
   선택에 사용하지 않는다.

재현 스크립트는 `scripts/audit_slot_predictor_leakage.py`, 산출물은
`outputs/slot_predictor_audit/`에 있다. 이 감사 자체는 2002-2022 결과를
본 사후 감사이므로 새 모델의 untouched 검증으로 사용할 수 없다.
